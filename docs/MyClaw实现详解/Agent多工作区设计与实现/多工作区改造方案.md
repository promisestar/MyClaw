## 1. 背景与问题

### 1.1 当前状态

MyClaw Agent 启动时通过环境变量 `WORKSPACE_PATH` 锁定一个工作区目录（默认 `~/.helloclaw/workspace`），Agent 进程中所有工具（Read/Write/Edit/Bash/RAG/Memory/Sessions/Tasks/Skills）的文件操作根目录都绑定到该路径，运行时不可变更。进程级的全局 Agent 单例使得所有会话共享同一个工作区。

### 1.2 核心矛盾

| 矛盾 | 描述 |
|------|------|
| **身份与工作区耦合** | `IDENTITY.md` / `SOUL.md` / `USER.md`（Agent 人格/身份）与项目代码挤在同一目录下，切到其他项目时人格丢失 |
| **工具根目录锁死** | `BashTool.allowed_directories`、`ReadTool.project_root` 等在 Agent 构造期写死，运行时不支持动态切换 |
| **用户操作范围受限** | 用户无法像 Cursor / WorkBuddy 那样在 UI 上选择"本次任务的工作区" |

### 1.3 改造目标

- **不改人格，换工作区**：Agent 身份（"我是谁"）永远从 `~/.helloclaw/identity/` 读取，工作区（"我要操作哪些文件"）按会话切换
- **进程不重启，工具重绑**：运行时通过 setter 重绑工具 `project_root`，毫秒级完成切换
- **前端一键选工作区**：顶栏加选择器，用户像 WorkBuddy 那样选择本地文件夹

## 2. 行业调研

### 2.1 OpenClaw 工作区设计

**来源**：[OpenClaw 官方文档 - Agent Workspace](https://docs.openclaw.ai/concepts/agent-workspace)

#### 2.1.1 核心架构

OpenClaw 实行 **Config 与 Workspace 彻底分离**：

```
~/.openclaw/                         ← 配置基座（进程级固定，不可切换）
├── openclaw.json                    # LLM / MCP / API Key
├── state/openclaw.sqlite            # 共享工作空间设置状态
├── agents/<agentId>/agent/
│   ├── auth-profiles.json           # 模型认证：OAuth + API Key
│   ├── openclaw-agent.sqlite        # 会话行、记录、per-agent 运行时状态
│   └── codex-home/                  # per-agent Codex 运行时
├── credentials/                     # 频道/提供方状态 + 旧版 OAuth
├── skills/                          # 托管技能
└── workspace/                       ← 工作区（可 per-agent 分离）
    ├── AGENTS.md  SOUL.md  IDENTITY.md  USER.md
    ├── TOOLS.md  HEARTBEAT.md  BOOTSTRAP.md
    ├── MEMORY.md
    ├── memory/YYYY-MM-DD.md          # 每日记忆日志
    ├── skills/                       # 工作空间特定技能（最高优先级）
    └── canvas/                       # Canvas UI 文件
```

#### 2.1.2 路径解析策略

> **Warning**: The workspace is the default cwd, **not a hard sandbox**. Tools resolve relative paths against the workspace, but absolute paths can still reach elsewhere on the host **unless sandboxing is enabled**.

沙箱可选，通过 `agents.defaults.sandbox` 启用后工具在 `~/.openclaw/sandboxes` 下操作。

#### 2.1.3 工作区文件加载机制

每次 session 启动时，OpenClaw 按以下顺序将 workspace 文件**自动注入 System Prompt**：

| 加载顺序 | 文件 | 注入位置 | 加载场景 |
|----------|------|----------|----------|
| 1 | AGENTS.md | `# Project Context` 第一个 | 每次 session |
| 2 | SOUL.md | 第二个 | 每次 session |
| 3 | TOOLS.md | 后续 | 每次 session |
| 4 | IDENTITY.md | 靠后 | 每次 session |
| 5 | USER.md | 靠后 | 每次 session |
| 6 | MEMORY.md | 截断后 | 仅主会话 |
| 7 | HEARTBEAT.md | 仅 heartbeat | 仅 heartbeat 模式 |

**核心机制**：
- 这些文件在 System Prompt 中，LLM **无需调用 `read` 工具**即可读到
- 单文件超 20KB → Head-Tail 截断（前 70% + 后 20%）
- 总预算超 150KB → 贪心分配，后续文件截断
- 基于 inode + mtime 缓存，未修改文件 <1ms 返回

#### 2.1.4 多 Agent 多工作区

```json5
{
  agents: {
    list: [
      { id: "work", workspace: "~/.openclaw/workspace-work" },
      { id: "personal", workspace: "~/.openclaw/workspace-personal" }
    ]
  },
  bindings: [
    { type: "route", agentId: "work", match: { channel: "slack" } },
    { type: "route", agentId: "personal", match: { channel: "telegram" } }
  ]
}
```

不同 channel 自动路由到不同 agent，不同 agent 拥有独立的 SOUL/MEMORY/USER.md。

#### 2.1.5 关键设计要点

| 要点 | 描述 |
|------|------|
| workspace 是 agent 的"家" | 存放行为规则和记忆，**不是代码仓库** |
| 非硬沙箱 | 相对路径解析到 workspace，绝对路径可出去（除非启用 sandbox） |
| Bootstrap 一次性引导 | `BOOTSTRAP.md` 仅新 workspace 创建一次，完成后删除 |
| Git 备份 | workspace 作为私有记忆，推荐放入私有 Git 仓库 |
| 多 workspace 警告 | 建议只保留一个活跃 workspace，避免状态漂移 |

#### 2.1.6 5 层目录扩展设计

OpenClaw 社区推荐的 5 层 workspace 扩展模型（来源：123AI）：

```
.
├── AGENTS.md SOUL.md USER.md IDENTITY.md TOOLS.md HEARTBEAT.md  # 顶层：工作规则层
├── context/               # 产出模板库（统一输出格式）
│   ├── BUG_REVIEW_TEMPLATE.md
│   └── KNOWLEDGE_NOTE_TEMPLATE.md
├── modules/               # 按任务域拆的模块
│   ├── daily-digest/
│   ├── job-market/
│   ├── research/
│   └── dev/
├── media/inbound/         # 缓存层（不沉淀知识）
└── vault/                 # 长期知识层（可对接 Obsidian）
    └── 09_AI/Openclaw/
        ├── 故障排查/
        ├── 机制解析/
        └── 操作指南/
```

**关键原则**：不按 `docs/` `data/` `output/` 按技术分类拆，按**任务目标**拆 — 一个目录对应一类稳定任务。

### 2.2 Cursor 工作区与 Rules 层级

**来源**：[Cursor 多项目 Rules 优先级文档](https://cursor.zone/faq/cursor-multi-project-rules-priority.html)

#### 2.2.1 Cursor 三层 Rules 架构

```
Cursor Settings → Rules                    ← User Rules（全局层，最高优先级）
    │
workspace.root/
    │ .cursor/rules/                        ← 全局项目规则（低优先级，全工作区生效）
    ├── frontend/
    │   └── .cursor/rules/                  ← 子项目规则（高优先级，覆盖全局冲突）
    ├── backend/
    │   └── .cursor/rules/
    └── shared/
        └── nested-dir/
            └── .cursor/rules/              ← 更深层规则（距离优先，最强势）
```

#### 2.2.2 优先级铁律

| 优先级 | 规则层级 | 生效范围 | 覆盖关系 |
|--------|----------|----------|----------|
| 🥇 最高 | User Rules | 全局所有项目 | 不可被任何层级覆盖 |
| 🥈 高 | 子项目 `.cursor/rules` | 当前子项目 | 覆盖工作区级冲突项 |
| 🥉 低 | 工作区根 `.cursor/rules` | 整个 workspace | 默认底线，可被子项目覆盖 |
| 🏅 最高 | 嵌套子目录 `.cursor/rules` | 最深匹配 | **距离优先**：距当前文件越近越强势 |

#### 2.2.3 核心机制提取

- **距离优先原则**：从当前正在编辑的文件所在目录开始，依次向外查找最近的 `.cursor/rules`
- **Glob 模式匹配**：规则可基于文件路径和 glob 模式确定适用范围
- **UI 规则提示**：界面会显示当前生效的规则

#### 2.2.4 对 MyClaw 的借鉴意义

| Cursor 机制 | MyClaw 映射 |
|-------------|-------------|
| User Rules（全局不可覆盖） | `~/.helloclaw/identity/SOUL.md` — Agent 人格永远加载 |
| Project Rules（`.cursor/rules`） | 项目目录下的 `AGENTS.md` — 项目行为规范 |
| 距离优先级 | **不直接采纳**（单 Agent 单工作区，不需要嵌套），但工作区 AGENTS.md 可叠加到全局 identity 上 |

### 2.3 WorkBuddy 同源底座与双模架构

**来源**：[WorkBuddy 核心技术架构深度拆解](https://cloud.tencent.com/developer/article/2651866)

#### 2.3.1 同源底座架构

WorkBuddy 与 CodeBuddy、QClaw 共享同一套 AI Agent 底层底座：

> **第一，技术复用。** 三个产品共享同一套核心技术，避免了重复开发。  
> **第二，能力互通。** CodeBuddy 的代码能力可以无缝集成到 WorkBuddy 中。  
> **第三，统一生态。** 三个产品共享同一个技能生态和同一个模型生态。

#### 2.3.2 双模运行机制

| 模式 | 适用场景 | 数据策略 |
|------|----------|----------|
| **云端沙箱模式** | 大量算力、定时任务、非敏感任务 | 所有计算在腾讯云隔离沙箱，任务完成后自动删除数据 |
| **本地执行模式** | 敏感数据、本地文件、内网资源 | 所有数据在用户本地，不上传云端；可访问本地文件和内网 |

**关键**：WorkBuddy **根据任务类型自动选择运行模式**，用户也可手动切换。

#### 2.3.3 空间-项目-任务三层架构

| 层级 | 职责 | 隔离粒度 |
|------|------|----------|
| **空间（Space）** | 独立隔离的工作环境 | 最高粒度，不同空间完全隔离 |
| **项目（Project）** | 空间内的目标工作合集 | 同一空间内按目标分组 |
| **任务（Task）** | 最小执行工作单元 | AI 执行的具体单元 |

**目录模型**：空间决定了根目录位置（COS bucket 或本地文件夹），项目和任务在空间下归集。

#### 2.3.4 对 MyClaw 的借鉴意义

| WorkBuddy 机制 | MyClaw 映射 |
|----------------|-------------|
| 同源底座（Agent Engine 跨产品共享） | MyClaw 进程唯一，全部会话共用同一 Agent/Tool Registry |
| 双模执行（云端沙箱/本地） | 暂不引入云端模式；沿用 `allowed_directories` 白名单沙箱 |
| 空间-项目-任务三层 | "工作区 = 空间级"，"会话 = 任务级"（不引入项目级以控制复杂度） |
| 自动模式选择 | 不在本方案实现 |

---

### 2.4 三项目共同规律

| 切入点 | OpenClaw | Cursor | WorkBuddy | **公共模式** |
|--------|----------|--------|-----------|-------------|
| 身份/人格存放 | workspace 内 SOUL/IDENTITY | User Rules（全局） | 空间级身份 | **人格应该跟项目/工作区分离** |
| 项目行为规则 | workspace 内 AGENTS.md | Project Rules（`.cursor/rules`） | 项目级配置 | **项目规则存项目目录里，叠加到全局规则上** |
| LLM/MCP 配置 | `~/.openclaw/` 下 | IDE Settings | 同源底座层 | **配置永远在固定目录，不随项目切换** |
| 工具沙箱 | 可选 `agents.defaults.sandbox` | IDE 内置沙箱 | 本地执行模式 | **沙箱是可选层，不是默认硬隔离** |
| 工作区切换 | per-agent 配置 | Multi-root workspace | 空间切换 | **切换开销要小，不重启进程** |
| 记忆持久化 | `MEMORY.md` + `memory/*.md` | Notepads | 项目级记忆 | **记忆可以跟项目走，也可以全局** |
| `project_root` / `workspace` | 可运行时指定 | 多根 workspace 索引 | 选中本地文件夹 | **File tool sandbox 根目录必须是可变的** |

**共识结论**：这三个产品的设计都在说同一件事——**Agent 的"灵魂"跟"工位"要解耦**。

## 3. MyClaw 当前架构审计

### 3.1 进程启动流程

```python
# backend/src/main.py (当前)
workspace_path = os.getenv("WORKSPACE_PATH", "~/.helloclaw/workspace")
workspace = WorkspaceManager(workspace_path)
workspace.ensure_workspace_exists()
_agent = MyClawAgent(workspace_path=workspace_path)  # 全局单例，workspace_path 写死
```

### 3.2 工具注册（沙箱白名单写死在构造期）

```python
# backend/src/agent/myclaw_agent.py (当前)
read_tool = ReadTool(project_root=self.workspace_path)
write_tool = WriteTool(project_root=self.workspace_path)
edit_tool = EditTool(project_root=self.workspace_path)
registry.register_tool(BashTool(
    allowed_directories=[self.workspace_path],  # 白名单写死
    default_workdir=self.workspace_path,
))
registry.register_tool(RAGTool(workspace_root=self.workspace_path))
```

### 3.3 身份/人格文件分布

| 文件 | 当前存放位置 | 性质 | 问题 |
|------|-------------|------|------|
| `IDENTITY.md` | `<workspace>/IDENTITY.md` | Agent 名字、emoji、vibe | 切工作区后人格丢失 |
| `SOUL.md` | `<workspace>/SOUL.md` | 人设、语气、边界 | 同上 |
| `USER.md` | `<workspace>/USER.md` | 用户画像、称呼方式 | 同上 |
| `AGENTS.md` | `<workspace>/AGENTS.md` | 行为规范、工具使用说明 | 合理 — 项目级行为规范 |
| `MEMORY.md` | `<workspace>/MEMORY.md` | 长期记忆 | 是否跟随项目可商榷 |

### 3.4 差距矩阵

| 差距项 | 当前 | 目标 | 对标 |
|--------|------|------|------|
| 身份/人格 | 跟 workspace 混在一起 | 分离到固定基座目录 | OpenClaw `~/.openclaw/` |
| 项目切换 | 不支持（进程启动期固定） | 运行时切换 | WorkBuddy 空间切换 |
| 工具白名单 | `BashTool.allowed_directories` 写死 | 运行时动态重绑 | Cursor Multi-root |
| 会话落点 | `<workspace>/sessions/` | `~/.helloclaw/sessions/`（全局，跨工作区共享） | 切项目不丢对话 |
| 任务落点 | `<workspace>/tasks/` | `~/.helloclaw/tasks/`（全局，跨工作区共享） | 切项目不丢任务进度 |
| 前端 UI | 无工作区选择器 | 有 | WorkBuddy 文件夹选择 |

## 4. 设计原则

遵循 **"最小改动量 + 最大借鉴行业实践"** 两项原则，确立以下设计约定：

### 4.1 三层划分（不是两层）

```
Layer 0: Agent 基座     ~/.helloclaw/          ← 进程固定，永不变化
Layer 1: 用户工作区     <任意项目目录>           ← 按 session 切换
Layer 2: 会话/任务      会话内的执行上下文        ← 不变（原有机制）
```

### 4.2 优先级链

借鉴 Cursor 的 Rules 优先级模型：

```
identity/SOUL.md   >   工作区/AGENTS.md   >   工具默认行为
   (最高，不可覆盖)     (叠加到 prompt，可自定义)     (代码中的默认值)
```

### 4.3 四个"不动"

1. **Agent 进程不重启** — 工具 setter 重绑 `project_root`，毫秒级
2. **LLM/MCP 配置不动** — 继续从 `~/.helloclaw/config.json` 读
3. **Tool Registry 不动** — 已有的 Read/Write/Edit/Bash/RAG/WebSearch/Skill/Memory 全保留
4. **System Prompt 核心结构不动** — 只在注入位置调整：identity 文件前置，AGENTS.md 后置

## 5. 模板部署流程审计

### 5.1 当前部署流程追踪

在 MyClaw 启动时（`main.py`），以下调用链负责将 `templates/` 下的模板部署到工作区目录：

```
main.py startup
  │
  ├── WorkspaceManager(workspace_path)
  │     └── self.sessions_path = <workspace_path>/sessions/
  │
  ├── workspace.ensure_workspace_exists()
  │     │
  │     ├── [1] ensure_global_config_exists()
  │     │     └── templates/config.json → ~/.helloclaw/config.json
  │     │         (仅首次，不覆盖已有)
  │     │
  │     ├── [2] os.makedirs(<workspace_path>)           ← 创建根目录
  │     ├── [3] os.makedirs(<workspace_path>/sessions/)  ← 创建会话目录
  │     │
  │     └── [4] for name in CONFIG_FILES:               ← 逐文件复制模板
  │           _create_default_config(name)
  │             ├── 读取 templates/<name>.md
  │             ├── 替换 {date} 占位符
  │             └── 写入 <workspace_path>/<name>.md
  │
  └── MyClawAgent(workspace_path)
        └── _build_system_prompt()
              ├── 读取 <workspace>/AGENTS.md      ← 必须存在（否则抛异常）
              ├── 读取 <workspace>/BOOTSTRAP.md    ← {date}（引导未完成时注入）
              ├── 读取 <workspace>/IDENTITY.md     ← 可选
              ├── 读取 <workspace>/USER.md         ← 可选
              └── 读取 <workspace>/SOUL.md         ← 可选
```

**关键发现**：
- 所有 `.md` 文件**平铺**在 `<workspace>/` 根目录下，和用户代码混在一起
- IDENTITY/SOUL/USER 是 Agent 的"灵魂"，但和 "工位"（项目文件）放在同一个桶里
- `_create_default_config()` 对 `CONFIG_FILES` 里的 6 个文件**一视同仁** — 不区分哪些是 Agent 级别的、哪些是项目级别的
- AGENTS.md 是`_build_system_prompt()` 的**骨干 prompt**（必须存在否则抛 `RuntimeError`）

### 5.2 新部署逻辑：两阶段部署

改造后，模板部署拆分为两个独立的阶段：**Agent 基座部署** 和 **工作区部署**。

**模板目录重组**：

```
backend/src/workspace/templates/
├── config.json                       # 全局配置模板（不变）
├── identity/                         # 🆕 Agent 基座模板
│   ├── IDENTITY.md
│   ├── SOUL.md
│   ├── USER.md
│   └── BOOTSTRAP.md                  # 一次性引导（建立 identity 后删除）
└── workspace/                        # 🆕 工作区模板
    ├── AGENTS.md
    └── HEARTBEAT.md
```

**Phase 1：Agent 基座部署**（进程启动时执行一次，目标 `~/.helloclaw/`）

```
backend 进程启动 (main.py)
  │
  ├── IdentityManager(home_path).ensure_exists()
  │     │
  │     ├── [1] 创建 ~/.helloclaw/identity/ 目录
  │     │
  │     ├── [2] 对每个 IDENTITY_FILES (IDENTITY, SOUL, USER):
  │     │     如果 ~/.helloclaw/identity/<name>.md 不存在:
  │     │       尝试从旧 workspace 迁移（兼容 v1 → v2）
  │     │       否则从 templates/identity/<name>.md 复制
  │     │
  │     └── [3] 如果 ~/.helloclaw/identity/BOOTSTRAP.md 不存在:
  │           从 templates/identity/BOOTSTRAP.md 复制
  │
  └── WorkspaceManager.ensure_global_config_exists()
        └── templates/config.json → ~/.helloclaw/config.json  (不变)
```

**Phase 2：工作区部署**（首次切换到某项目目录时执行，目标 `<project>/.myclaw/`）

```
前端选择工作区 → POST /api/workspace/switch { path: "/path/to/project" }
  │
  ├── auth.is_allowed(path) 校验白名单
  │
  └── workspace.ensure_project_workspace("/path/to/project")
        │
        ├── [1] 创建 /path/to/project/.myclaw/ 目录
        ├── [2] 创建 /path/to/project/.myclaw/uploads/
        ├── [3] 创建 /path/to/project/.myclaw/skills/
        ├── [4] 创建 /path/to/project/.myclaw/automations/
        │
        └── [5] 如果 /path/to/project/.myclaw/AGENTS.md 不存在:
              从 templates/workspace/AGENTS.md 复制
              (HEARTBEAT.md 同理 - 可选，只做不存在时创建)
              （sessions/tasks 已提升到全局 ~/.helloclaw/，此处不再创建）
```

**核心差异对比**：

| 维度 | 旧部署逻辑 | 新部署逻辑 |
|------|-----------|-----------|
| 模板来源 | `templates/` 平铺 7 个文件 | `templates/identity/` + `templates/workspace/` 分层 |
| 部署时机 | 启动时一次性全量部署 | Phase 1（启动时基座）+ Phase 2（首次切换工作区时懒部署） |
| 目标路径 | `<workspace>/` 根目录平铺 | Agent 基座 → `~/.helloclaw/identity/`；工作区 → `<project>/.myclaw/` |
| 身份文件 | 和用户代码混在一起 | 隔离在 `~/.helloclaw/identity/`，用户永远看不到 |
| AGENTS.md | 启动时必须存在于 workspace | 启动时从基座 AGENTS.md 读取，工作区 `.myclaw/AGENTS.md` 为覆盖项 |
| 文件隔离 | 所有文件散落在项目根目录 | 统一归拢到 `.myclaw/` 子目录，用户项目根目录保持整洁 |

## 6. 目标架构

### 6.1 目录结构

```
~/.helloclaw/                          ← Agent 基座（进程级固定，永不可切换）
├── config.json                        # LLM / MCP / API Key（已有，不变）
├── identity/                          # 🆕 身份/人格基座
│   ├── IDENTITY.md                    # Agent 名字、emoji、vibe
│   ├── SOUL.md                        # 人格、语气、边界
│   ├── USER.md                        # 用户画像、呼叫方式
│   └── BOOTSTRAP.md                   # 一次性引导（identity 建立后自动删除）
├── sessions/                          # 🆕 会话历史（全局共享，跨工作区）
├── tasks/                             # 🆕 任务追踪与 Plan 暂存（全局共享，跨工作区）
├── memory/                            # 全局长期记忆（向量化，已有的 RAG）
│   └── vector_store.db
└── skills/                            # 全局可复用 Skill

<用户任意项目目录>/                      ← 工作区（前端可选切换）
├── .myclaw/                           # 🆕 所有 Agent 工作区文件归拢至此，不污染项目根目录
│   ├── AGENTS.md                      # 项目行为规范（可选，不存在时使用默认值）
│   ├── HEARTBEAT.md                   # 心跳任务（可选）
│   ├── uploads/                       # per-workspace 文件上传
│   ├── skills/                        # per-workspace Skill（优先级高于全局）
│   └── automations/                   # per-workspace 定时任务
└── [用户自己的代码/文件/目录...]
```

> **设计决策**：为什么用 `.myclaw/` 而不是像 Cursor 那样用 `.cursor/` 或像 VS Code 用 `.vscode/`？
> 1. 隐藏目录 `.myclaw/` 在 Linux/macOS 下自动隐藏，不破坏项目根目录整洁度
> 2. 参考 WorkBuddy "空间-项目-任务"三层模型 — 工作区文件归拢一处，`git add` 或 `.gitignore` 时一目了然
> 3. `.myclaw/` 可以作为一个整体被 `.gitignore` 排除，也可以选择性提交 `AGENTS.md` 给团队共享
> 4. 对标 OpenClaw 的 `~/.openclaw/workspace/` 设计 — MyClaw 选择把 workspace-level 文件放在项目内（让不同项目有不同 AGENTS.md），而非全局目录

> **设计决策（v1.1）**：会话历史与 Task 历史为何提升到全局？
> 1. 切工作区不丢对话/任务进度，符合「不改人格、换工位」的产品体验
> 2. 避免 `SessionStore` 构造期缓存 `session_dir` 导致切区后仍写入旧路径的隐蔽 bug
> 3. `bind_workspace` 少绑 2 个引用点（`session_dir` / `_persist_dir`），切换路径更简单

```python
"""Agent 身份管理器 — 从基座目录加载身份/人格文件，并负责首次部署"""

import os
import shutil
from pathlib import Path
from typing import Optional

# 身份/人格文件列表（不含 BOOTSTRAP - 引导完成后会被删除）
IDENTITY_FILES = ["IDENTITY", "SOUL", "USER"]

# 引导文件
BOOTSTRAP_FILE = "BOOTSTRAP"

# 模板目录
TEMPLATES_DIR = Path(__file__).parent / "templates"
IDENTITY_TEMPLATES_DIR = TEMPLATES_DIR / "identity"


class IdentityManager:
    """管理 Agent 的身份、人格、用户画像文件

    所有文件从固定的 AGENT_HOME/identity/ 下读取，不随工作区切换而改变。
    负责首次部署时从模板复制 identity 文件到基座目录。
    """

    def __init__(self, home_dir: str = "~/.helloclaw"):
        self.home_dir = os.path.expanduser(home_dir)
        self.identity_dir = os.path.join(self.home_dir, "identity")
        self._migration_marker = os.path.join(self.home_dir, ".v2_migration_done")

    def _deploy_from_template(self, filename: str):
        """从模板部署单个文件（不覆盖已有）"""
        target = os.path.join(self.identity_dir, filename)
        if os.path.exists(target):
            return
        src = IDENTITY_TEMPLATES_DIR / filename
        if src.exists():
            os.makedirs(self.identity_dir, exist_ok=True)
            shutil.copy2(src, target)
            print(f"📝 已从模板部署: {target}")
        else:
            self.save_file(filename, f"# {filename.replace('.md', '')}\n\n（待配置）")

    def _migrate_from_workspace(self, filename: str, old_workspace: str):
        """从旧 workspace 目录迁移文件到 identity 目录"""
        target = os.path.join(self.identity_dir, f"{filename}.md")
        if os.path.exists(target):
            return
        old = os.path.join(old_workspace, f"{filename}.md")
        if os.path.exists(old):
            os.makedirs(self.identity_dir, exist_ok=True)
            shutil.copy2(old, target)
            print(f"📦 已从旧工作区迁移: {target}")

    def ensure_exists(self, old_workspace: Optional[str] = None):
        """Phase 1 部署：确保 identity 文件存在

        1. 如果 .v2_migration_done 标记不存在 → 尝试从旧 workspace 迁移
        2. 迁移后或新安装 → 从 templates/identity/ 复制缺失文件
        3. 确保 BOOTSTRAP.md 存在（仅新装/引导未完成时）
        4. 写入迁移完成标记
        """
        os.makedirs(self.identity_dir, exist_ok=True)

        # Step 1: 从旧 workspace 迁移（仅首次）
        if old_workspace and not os.path.exists(self._migration_marker):
            migrated = False
            for name in IDENTITY_FILES:
                self._migrate_from_workspace(name, old_workspace)
                migrated = True
            if migrated:
                print("📦 V1 → V2 身份文件迁移完成")

        # Step 2: 从模板填充缺失文件
        for name in IDENTITY_FILES:
            self._deploy_from_template(f"{name}.md")

        # Step 3: 确保 BOOTSTRAP 存在（引导完成后会自动删除）
        bootstrap_path = os.path.join(self.identity_dir, "BOOTSTRAP.md")
        if not os.path.exists(bootstrap_path):
            self._deploy_from_template("BOOTSTRAP.md")

        # Step 4: 标记迁移完成
        if not os.path.exists(self._migration_marker):
            with open(self._migration_marker, "w") as f:
                f.write("done")

    def is_onboarding_completed(self) -> bool:
        """入职是否完成 = BOOTSTRAP.md 已删除"""
        bootstrap_path = os.path.join(self.identity_dir, "BOOTSTRAP.md")
        return not os.path.exists(bootstrap_path)

    def save_file(self, filename: str, content: str):
        """保存 identity 文件"""
        os.makedirs(self.identity_dir, exist_ok=True)
        path = os.path.join(self.identity_dir, filename)
        with open(path, "w", encoding="utf-8") as f:
            f.write(content)

    def _load_raw(self, filename: str) -> Optional[str]:
        path = os.path.join(self.identity_dir, filename)
        if not os.path.exists(path):
            return None
        with open(path, "r", encoding="utf-8") as f:
            return f.read()

    def load_name(self, name: str) -> Optional[str]:
        return self._load_raw(f"{name}.md")

    @property
    def identity(self) -> str: return self._load_raw("IDENTITY.md") or ""
    @property
    def soul(self) -> str: return self._load_raw("SOUL.md") or ""
    @property
    def user(self) -> str: return self._load_raw("USER.md") or ""
    @property
    def bootstrap(self) -> Optional[str]: return self._load_raw("BOOTSTRAP.md")
```

```python
"""工作区授权管理 — 维护用户已授权的工作区白名单"""

import json
import os
from pathlib import Path
from typing import List


AUTH_FILE = os.path.expanduser("~/.helloclaw/workspaces.json")


def _load() -> List[str]:
    if not os.path.exists(AUTH_FILE):
        return []
    try:
        with open(AUTH_FILE, "r", encoding="utf-8") as f:
            data = json.load(f)
        return [os.path.abspath(os.path.expanduser(p))
                for p in data if isinstance(p, str)]
    except (json.JSONDecodeError, IOError):
        return []


def _save(paths: List[str]):
    os.makedirs(os.path.dirname(AUTH_FILE), exist_ok=True)
    with open(AUTH_FILE, "w", encoding="utf-8") as f:
        json.dump(paths, f, indent=2, ensure_ascii=False)


def list_allowed_workspaces() -> List[str]:
    """返回所有已授权且存在的目录"""
    return [p for p in _load() if os.path.isdir(p)]


def is_allowed(workspace_path: str) -> bool:
    abs_path = os.path.abspath(os.path.expanduser(workspace_path))
    return os.path.isdir(abs_path) and abs_path in _load()


def authorize(workspace_path: str) -> bool:
    """授权一个新工作区"""
    abs_path = os.path.abspath(os.path.expanduser(workspace_path))
    if not os.path.isdir(abs_path):
        return False
    current = _load()
    if abs_path not in current:
        current.append(abs_path)
        _save(current)
    return True


def revoke(workspace_path: str):
    """撤销一个工作区授权"""
    current = _load()
    abs_path = os.path.abspath(os.path.expanduser(workspace_path))
    if abs_path in current:
        current.remove(abs_path)
        _save(current)
```

#### 7.2.3 修改：`workspace/manager.py`

删减内容：

重构后的 `WorkspaceManager`：

```python
"""工作空间管理器 (V2) — 仅管理项目工作区的 .myclaw/ 子目录"""
import os
from datetime import datetime
from pathlib import Path
from typing import Optional

# 工作区模板目录
WORKSPACE_TEMPLATES_DIR = TEMPLATES_DIR / "workspace"

# 工作区级 .myclaw/ 子目录
# sessions 和 tasks 已迁移到全局 ~/.helloclaw/，跨工作区共享
WORKSPACE_SUBDIRS = ["uploads", "skills", "automations"]

# 工作区级配置文件
WORKSPACE_CONFIG_FILES = ["AGENTS"]  # 仅 AGENTS.md 为工作区级配置
WORKSPACE_OPTIONAL_FILES = ["HEARTBEAT"]  # 可选文件，不存在不报错


class WorkspaceManager:
    """管理单个项目工作区的 .myclaw/ 子目录"""

    def __init__(self, workspace_path: str = "."):
        self.workspace_path = os.path.abspath(os.path.expanduser(workspace_path))
        self.claw_dir = os.path.join(self.workspace_path, ".myclaw")

    @property
    def sessions_path(self) -> str:
        """会话存储路径（全局共享，跨工作区）。"""
        path = os.path.expanduser("~/.helloclaw/sessions")
        os.makedirs(path, exist_ok=True)
        return path

    @property
    def tasks_path(self) -> str:
        """任务追踪器存储路径（全局共享，跨工作区）。"""
        path = os.path.expanduser("~/.helloclaw/tasks")
        os.makedirs(path, exist_ok=True)
        return path

    @property
    def uploads_path(self) -> str:
        return os.path.join(self.claw_dir, "uploads")

    @property
    def skills_path(self) -> str:
        return os.path.join(self.claw_dir, "skills")

    @property
    def automations_path(self) -> str:
        return os.path.join(self.claw_dir, "automations")

    def _deploy_from_template(self, name: str):
        """从 workspace 模板部署单个文件到 .myclaw/（不覆盖已有）"""
        target = os.path.join(self.claw_dir, f"{name}.md")
        if os.path.exists(target):
            return
        src = WORKSPACE_TEMPLATES_DIR / f"{name}.md"
        if src.exists():
            with open(src, "r", encoding="utf-8") as f:
                content = f.read()
            content = content.replace("{date}", datetime.now().strftime("%Y-%m-%d"))
            os.makedirs(self.claw_dir, exist_ok=True)
            with open(target, "w", encoding="utf-8") as f:
                f.write(content)
            print(f"📝 已从模板部署: {target}")

    def ensure_project_workspace(self):
        """Phase 2 部署：确保 .myclaw/ 目录结构存在

        每次切换到新工作区时调用（首次部署模板文件，后续仅确保目录存在）。
        """
        # 创建 .myclaw/ 子目录
        for subdir in WORKSPACE_SUBDIRS:
            os.makedirs(os.path.join(self.claw_dir, subdir), exist_ok=True)

        # 部署必需的工作区配置文件
        for name in WORKSPACE_CONFIG_FILES:
            self._deploy_from_template(name)

        # 部署可选配置文件
        for name in WORKSPACE_OPTIONAL_FILES:
            self._deploy_from_template(name)

    def get_config_path(self, name: str) -> str:
        return os.path.join(self.claw_dir, f"{name}.md")

    def load_config(self, name: str) -> Optional[str]:
        path = self.get_config_path(name)
        if not os.path.exists(path):
            return None  # 不抛异常 - 工作区 AGENTS.md 可能不存在
        with open(path, "r", encoding="utf-8") as f:
            return f.read()

    def save_config(self, name: str, content: str):
        os.makedirs(self.claw_dir, exist_ok=True)
        with open(self.get_config_path(name), "w", encoding="utf-8") as f:
            f.write(content)

    def list_configs(self) -> list:
        configs = []
        for name in WORKSPACE_CONFIG_FILES + WORKSPACE_OPTIONAL_FILES:
            if os.path.exists(self.get_config_path(name)):
                configs.append(name)
        return configs

    def _clear_sessions(self):
        """清除全局 ~/.helloclaw/sessions/ 下所有会话。"""
        if os.path.exists(self.sessions_path):
            for name in os.listdir(self.sessions_path):
                if name.endswith(".json"):
                    os.remove(os.path.join(self.sessions_path, name))

    def reset_to_templates(self, reset_sessions: bool = False):
        """重置当前工作区的 .myclaw/ 配置文件到初始模板"""
        for name in WORKSPACE_CONFIG_FILES + WORKSPACE_OPTIONAL_FILES:
```

**新增方法：`bind_workspace()`**：

```python
def bind_workspace(self, workspace_path: str):
    """切换到指定工作区（运行时动态重绑工具根目录 + 部署 .myclaw/ 结构）

    调用时机：
    - POST /api/workspace/switch 接口
    - 前端发送消息时附带 workspace_path 参数

    Args:
        workspace_path: 用户选择的工作区目录

    Raises:
        ValueError: 工作区未授权或路径无效
    """
    workspaces_auth = __import__("src.workspace.auth",
                                 fromlist=["is_allowed"]).is_allowed
    if not workspaces_auth(workspace_path):
        raise ValueError(f"工作区未授权: {workspace_path}")

    abs_path = os.path.abspath(os.path.expanduser(workspace_path))
    self._current_workspace = abs_path

    # Phase 2 部署：确保 .myclaw/ 子目录结构存在
    self.workspace = WorkspaceManager(abs_path)
    self.workspace.ensure_project_workspace()

    # sessions/tasks 已全局化到 ~/.helloclaw/，此处无需重绑 session_dir / _persist_dir

    # 重绑工具沙箱根目录
    for tool_name, tool in self._get_workspace_tools().items():
        if hasattr(tool, "project_root"):
            setattr(tool, "project_root", abs_path)
        elif hasattr(tool, "allowed_directories"):
            setattr(tool, "allowed_directories", [abs_path])
            setattr(tool, "default_workdir", abs_path)
            setattr(tool, "_cwd", None)  # 重置 cd 历史记忆

def _get_workspace_tools(self) -> dict:
    """返回需要重绑的工作区相关工具"""
    return {
        k: v for k, v in self._tool_registry._tools.items()
        if k in ("read", "write", "edit", "bash", "rag")
    }

@property
def current_workspace(self) -> str:
    return self._current_workspace
```

```python
def _build_system_prompt(self) -> str:

    调整后的注入顺序：
    1. 基座 AGENTS.md 作为 prompt 骨架（从 ~/.helloclaw/identity/ 附近的全局版本）

    # ... 其余注入逻辑不变（长期记忆、子代理、Heartbeat 等）

    return base_prompt + "\n\n" + "\n".join(context_parts)
```

```typescript
import { defineStore } from 'pinia';
import { ref, computed } from '@vue/composition-api';
import { listWorkspaces, switchWorkspace, authorizeWorkspace } from '@/api/workspace';

export const useWorkspaceStore = defineStore('workspace', () => {
  const current = ref('');
  const history = ref<string[]>([]);
  const loading = ref(false);

  const currentName = computed(() => {
    if (!current.value) return '未选择工作区';
    const parts = current.value.split(/[/\\]/);
    return parts[parts.length - 1] || current.value;
  });

  async function init() {
    try {
      const res = await listWorkspaces();
      history.value = res.workspaces || [];
      current.value = res.current || '';
    } catch {
      // 静默失败
    }
  }

  async function select(path: string) {
    loading.value = true;
    try {
      await switchWorkspace(path);
      current.value = path;
      if (!history.value.includes(path)) {
        history.value.unshift(path);
      }
    } finally {
      loading.value = false;
    }
  }

  async function openLocal() {
    // 调系统文件选择对话框（Electron / File System Access API）
    // 或让用户手动输入路径
    const path = prompt('请输入工作区目录路径：');
    if (!path) return;
    await authorize(path);
    await select(path);
  }

  return { current, currentName, history, loading, init, select, openLocal };
});
```

## 9. 安全性设计

### 8.1 沙箱机制（保持不变 + 增强）

现有 `BashTool` 的危险命令拦截完整保留（`_DANGEROUS_PATTERNS` 列表包括 rm -rf、sudo、mkfs 等），不做任何删除。

**增强点**：运行时 `bind_workspace()` 动态更新 `BashTool.allowed_directories`，确保 `cd` 无法跳出白名单：

```python
def bind_workspace(self, workspace_path: str):
    abs_path = os.path.abspath(workspace_path)
    self.allowed_directories = [abs_path]
    self.default_workdir = abs_path
    self._cwd = None  # 重置 cd 历史
```

### 8.2 白名单模型（新增）

| 层级 | 机制 | 说明 |
|------|------|------|
| 进程级 | `~/.helloclaw/identity/` 只读 | 身份文件不从请求修改 |
| 用户级 | `~/.helloclaw/workspaces.json` 白名单 | 用户必须显式授权每个目录 |
| 运行时 | API 校验 + 工具重绑 | 每次切换先验证白名单再重绑 |
| 工具级 | `BashTool.allowed_directories` 白名单 | 命令执行只能在授权目录内 |

### 8.3 禁止的行为

- **禁止** 前端传任意路径越级到 `/etc` → 后端必须校验 `is_allowed()`
- **禁止** 切换工作区时不重置 BashTool 的 `_cwd`（防止 cd 跨工作区）
- **禁止** API key 或敏感配置泄露到工作区目录

3. 写入 `~/.helloclaw/.v2_migration_done` 标记，后续启动不再重复迁移
4. 如果旧 workspace 也不存在 → 直接从 `templates/identity/` 部署新文件

### 11.2 与三项目的差异说明

| 决策 | MyClaw 选择 | 原因 |
|------|------------|------|
| identity 与 workspace 分离 | ✅ 是 | 借鉴 OpenClaw + Cursor 共识 |
| 沙箱硬隔离（Docker/LXC） | ❌ 不引入 | 改动量太大，沿用 `allowed_directories` 白名单 |
| 云端沙箱模式 | ❌ 不引入 | WorkBuddy 云沙箱需要腾讯云基础设施 |
| 多 Agent 不同 identity | ❌ 不引入 | 当前单 Agent 全局单例，多 Agent 为远期目标 |
| 5 层 workspace 扩展目录 | ❌ 不引入 | 太复杂，`.myclaw/` 扁平结构更可控 |
| Git 自动备份 workspace | ❌ 不引入 | 交由用户自行管理 |
| 空间-项目-任务三层 | ❌ 不引入项目层 | Workspace = 空间级足够，session = 任务级 |
| 会话/任务按工作区隔离 | ❌ 改为全局 | `~/.helloclaw/sessions|tasks/` 跨工作区共享，切项目不丢历史 |
| 距离优先嵌套 rules | ❌ 不引入 | 单项目单 AGENTS.md，不需要子目录规则 |
