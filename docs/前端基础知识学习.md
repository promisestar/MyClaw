## Vue 与前端基础

本章涵盖理解 monorepo-project 项目代码所需的前端核心概念和 Vue 2 基础知识。

### 一、前端三件套在项目中的体现

#### HTML → `<template>`

Vue 单文件组件 (`.vue`) 的 `<template>` 本质是 HTML 片段，但多了 Vue 特有语法：

```vue
<template>
  <div class="event-detail">
    <!-- 条件渲染：v-if 控制元素是否存在于 DOM -->
    <template v-if="isReady">
      <DetailPageHeader :event="eventData" />
    </template>

    <!-- 列表渲染：v-for 循环生成元素 -->
    <swiper-item v-for="item in banners" :key="item.id">
      <img :src="item.image" />
    </swiper-item>

    <!-- 事件绑定：@click 监听用户操作 -->
    <button @click="onRetry">重新加载</button>

    <!-- 文本插值：{{ }} 显示变量值 -->
    <p>{{ eventTitle }}</p>
  </div>
</template>
```

#### CSS → `<style scoped>`

```vue
<style lang="scss" scoped>
// scoped 属性让样式只作用于当前组件，防止全局污染
// 项目中统一使用 BEM 命名（Block__Element--Modifier）
.event-detail {
  width: 750px;

  &__main {
    display: flex;
  }

  &__loading-text {
    color: var(--color-lightgray);  // ← 使用 CSS 变量，不用硬编码颜色
  }
}
</style>
```

**本项目关键约定**：
- 颜色值优先用 CSS 变量（`var(--color-heavygray)` 而非 `#262e40`）
- 禁止 `gap` 属性（安卓兼容性问题）→ 用 `margin-left` + `> * + *` 替代
- SASS 变量用破折号命名（`$my-var`），不用驼峰

#### JavaScript/TypeScript → `<script lang="ts">`

```vue
<script lang="ts">
import { defineComponent, ref, computed } from '@vue/composition-api';
import AppBridge from '@company/shared-base/bridge';

export default defineComponent({
  name: 'DetailPage',
  props: {
    eventId: { type: String, required: true },
  },
  setup(props) {
    const count = ref(0);                    // 响应式变量
    const double = computed(() => count.value * 2);  // 计算属性
    return { count, double };
  },
});
</script>
```

### 二、Vue 2 + Composition API 核心概念

#### 1. 组件 = Template + Script + Style

Vue 单文件组件（`.vue`）将模板、逻辑、样式封装在同一个文件中：

```
<template>   ← 写结构：HTML + Vue 指令
<script>     ← 写逻辑：数据、方法、生命周期
<style>      ← 写样式：CSS/SCSS，加 scoped 隔离
```

#### 2. 响应式系统

Vue 会自动追踪数据变化并更新 DOM。核心 API：

| API | 用途 | 示例 |
|-----|------|------|
| `ref()` | 包裹基本类型（number/string/boolean），访问需 `.value` | `const count = ref(0); count.value++` |
| `reactive()` | 包裹对象，直接访问属性 | `const state = reactive({ name: '' }); state.name = 'hello'` |
| `computed()` | 派生数据，依赖变化自动重算，有缓存 | `const fullName = computed(() => first + last)` |
| `watch()` | 监听某个值的变化后执行副作用 | `watch(eventId, (newVal) => loadData(newVal))` |

```typescript
// 实际项目示例 — module-detail-page/Index.vue
const eventId = computed(() => store.state.eventData?.id || pageParams.event_id || '');
// eventId 会自动跟随 store.state.eventData 或 pageParams 的变化而更新，无需手动赋值

const isReady = computed(() => store.state.loadStatus === 'success');
// 模板里写 v-if="isReady"，数据加载成功后自动显示内容
```

#### 3. 组件通信：Props 向下，Emit 向上

```vue
<!-- 父组件 -->
<TodoItem
  :item="todo"           ← Props：父传子（数据 下传）
  @update="handleUpdate" ← Emit：子传父（事件 上传）
/>
```

```typescript
// 子组件 TodoItem.vue
export default defineComponent({
  props: {
    item: { type: Object as PropType<TodoItem>, required: true },
  },
  emits: ['update', 'delete'],   // 声明会 emit 哪些事件
  setup(props, { emit }) {
    const onEdit = () => {
      emit('update', props.item.id, newText);  // 子通知父
    };
    return { onEdit };
  },
});
```

**核心原则**：父组件永远不直接修改子组件的数据，子组件永远不直接修改 `props`。

#### 4. Setup 函数的执行时机

```typescript
export default defineComponent({
  setup(props) {
    // setup() 在 beforeCreate 阶段执行
    // 此时 this 不可用（Composition API 不需要 this）
    // 这是编写 所有业务逻辑 的地方

    const data = ref(null);

    onMounted(() => {
      // DOM 已挂载，可以安全操作
      loadData();
    });

    return { data };  // 返回的变量在 <template> 中可用
  },
});
```

#### 5. 常用指令速查

| 指令 | 含义 | 示例 |
|------|------|------|
| `v-if="x"` | 条件为真才渲染（DOM 不存在） | `<div v-if="isReady">` |
| `v-show="x"` | 条件为假隐藏（DOM 存在，`display:none`） | `<div v-show="isOpen">` |
| `v-for` | 循环渲染 | `<li v-for="item in list" :key="item.id">` |
| `v-model` | 双向绑定（表单用） | `<input v-model="keyword" />` |
| `:prop="val"` | 动态属性绑定（等价 `v-bind:prop`） | `<img :src="imageUrl" />` |
| `@click="fn"` | 事件监听（等价 `v-on:click`） | `<button @click="onSubmit">` |

#### 6. Options API vs Composition API

```typescript
// Options API（旧）— 按选项类型组织代码
export default {
  data() { return { count: 0 }; },
  methods: { increment() { this.count++; } },
  computed: { double() { return this.count * 2; } },
  mounted() { console.log('ready'); },
};

// Composition API（新，本项目标准）— 按逻辑关注点组织代码
export default defineComponent({
  setup() {
    const count = ref(0);                              // 数据
    const increment = () => { count.value++; };         // 方法
    const double = computed(() => count.value * 2);     // 派生
    onMounted(() => { console.log('ready'); });         // 生命周期
    return { count, increment, double };
  },
});
```

**本项目选用 Composition API 的原因**：同一需求的 data + methods + watch 可以写在一起，不需要在选项块之间反复横跳。

### 三、本项目特有约定速查

| 场景 | 约定 |
|------|------|
| 网络请求 | 用 `AppBridge.request(url, Method, params)`，禁止 `fetch`/`axios` |
| 路由跳转 | 用 `AppRouter.routeTo({ name, query })`，禁止 `location.href` |
| 平台判断 | 用 `PlatformEnum` 枚举，禁止字符串比对 |
| 数据上报 | `AppBridge.mtaReport({ busi, eventName })` |
| 状态管理 | 单页面用模块级单例 store，跨模块用 Pinia |
| 禁止项 | `v-html`、`<script setup>`、自定义指令、`!important`、`var` |
| 命名 | 变量/函数 camelCase，组件 PascalCase，CSS 类 BEM |
| 颜色 | 优先用 `var(--color-xxx)` 而非硬编码色值 |
| 依赖导入 | 通过 `@vue/composition-api` 导入，不用 `vue` 直接 import |

### 每个文件/目录的作用说明

#### 1. `package.json` — 模块身份标识

```json
{
  "name": "@company/app-discovery",
  "appGroupName": "app-discovery",  // ← Hel 模块唯一标识，preFetchLibApi 的参数
  "main": "entrance/libProperties.js",    // ← Hel 加载入口
  "version": "1.0.99",
  "dependencies": { ... }                 // ← 声明依赖，pnpm workspace 自动解析
}
```

- `appGroupName` 是最关键的字段——壳工程 `preFetchLibApi('app-discovery')` 的参数就是它
- `main` 告诉 Hel 构建系统"把这个文件作为模块入口"

#### 2. `main.js` — Hel 注册入口

```js
import { appGroupName } from './package.json';
import { libReady } from '@company/hel-lib-proxy';

(async function () {
  const libProperties = await import('./entrance/libProperties');
  libReady(appGroupName, libProperties.default);  // ← 向 Hel 代理注册
}()).catch(console.error);
```

**作用**:模块被加载时第一时间执行，调用 `libReady` 把组件清单注册到 Hel 代理，后续任何 `preFetchLibApi` 调用都能拿到这些组件。这发生在模块代码层面，不涉及 DOM 渲染。

#### 3. `entrance/libProperties.js` — 组件导出清单

```js
import Index from '../Index.vue';
import Discovery from '../components/discover-content/h5/index.vue';
import ContentDetail from '../components/content-detail/index.vue';
// ... 更多组件

export default {
  Index,              // → 壳里 lib.Index = Index.vue
  Discovery,          // → 壳里 lib.Discovery = discover-content/h5/index.vue
  ContentDetail,   // → 壳里 lib.ContentDetail = content-detail/index.vue
};
```

**作用**:这是"对外暴露什么"的配置文件。新增一个可被外部使用的组件，必须在这里注册。内部子组件不需要注册。

#### 4. `Index.vue` — 主组件

模块的根级组件。注意两种实际情况：

- **直接作为业务入口**：如 `module-detail-page/Index.vue` 是 615 行的事件详情页，壳路由直接渲染它
- **保留脚手架占位**：如 `app-discovery/Index.vue` 是模块创建时的模板文件（`ref('Hello World')` + `<TestComponent />`），真正的业务组件放在 `components/` 下并以语义化命名导出（`Discovery`、`ContentDetail` 等）

> **常见误区**：不要以为根级 `Index.vue` 一定就是模块入口。多组件 Hel 包通常把真实业务代码放在 `components/` 下，根 `Index.vue` 只是创建时生成的脚手架。判断标准是看 `libProperties.js` 中哪个导出的组件被壳路由实际引用。

#### 5. `loadApp.js` — 独立挂载逻辑

```js
// ⚠️ app-discovery 和 module-detail-page 目前都缺失此文件
// 标准写法示例:
import Vue from 'vue';
import Index from './Index.vue';

new Vue({
  render: h => h(Index, { props: { /* mock params */ } }),

```

**作用**:脱离壳工程，在本地独立启动模块。创建 Vue 实例，把 `Index.vue` 挂到一个空的 HTML 页面上，配合 `TestContainer.vue` 和 `api/mock.ts` 实现纯本地调试。

#### 7. `api/{service}/` — 接口层（三层结构）

```
api/contentDetail/
├── index.ts    # 封装 AppBridge.request，返回 Promise
├── types.ts    # interface EventEntity, EventNewsItem 等类型定义
```

| 文件 | 作用 |
|------|------|
| `index.ts` | 封装网络请求，屏蔽 `AppBridge.request` 的多端差异，组件只调用 `getContentDetail({event_id})` 不关心底层 |

#### 8. `store/use{XX}Store.ts` — 状态管理

`module-detail-page` 有 `store/useDetailPageStore.ts`（281 行），`app-discovery` 没有 store（全部在组件内用 `ref`/`reactive` 自管）。

**实现模式 — 模块级单例 Store（非 Pinia）**：

项目实际采用的是一种轻量模式：在模块顶层创建 `reactive` 对象 + computed getter + action 函数，再通过 `useXxxStore()` 导出。由于 JS 模块在同一个应用实例下只执行一次，所有 import 该函数的组件共享同一份 state：

```typescript
// store/useDetailPageStore.ts — 核心结构
import { reactive, computed } from '@vue/composition-api';

// ① 模块顶层 reactive = 全局单例（任何组件 import 即共享）
const state = reactive({
  eventData: null,
  currentEventIndex: 0,
  loadStatus: 'idle',
  // ... 共 10 个字段
});

// ② computed 派生数据（不存冗余，自动随 state 更新）
const currentNews = computed(() => {
  const list = state.eventData?.event_news;
  return list?.[state.currentEventIndex] || null;
});

// ③ 动作方法（直接修改 state，Vue 响应式自动通知所有 consumer）
const setEventResp = (resp) => {
  state.eventData = resp.event;
  state.loadStatus = 'success';
};

const resetStore = () => {
  state.eventData = null;
  state.currentEventIndex = 0;
  // ... 重置所有字段
};

// ④ 导出工厂函数（每次调用返回同一份 state 引用）
export const useDetailPageStore = () => ({
  state,
  currentNews,
  setEventResp,
  resetStore,
});
```

**与 Pinia 的关键区别**：
- Pinia 需要壳工程统一注册 `createPinia()` 实例，多端兼容成本高
- 模块级单例是纯 JS 模块缓存行为，不依赖任何框架注册，小程序/H5/App 开箱即用

**选择原则**：
- **单页面模块**（如 `module-detail-page`）→ 组件内 state 通常就够，store 主要用于「多个子组件 + 浮层共享加载态 / 选中态」
- **多页面/无 store 的模块**（如 `app-discovery`）→ 把所有状态放在父组件 `setup()` 里，通过 props 下发、emit 上传，避免模块级单例的 `resetStore` 时机陷阱
- **跨模块共享** → 用 Pinia，不要用模块级单例（作用域局限在该 Hel 包内）

#### 9. `hooks/` — 可复用逻辑

`app-discovery/hooks/` 包含 3 个 composable，展示了真实项目中的典型用途：

```
hooks/
├── useOverlayLifecycle.ts   # 浮层生命周期：H5 端 body 锁滚 + Escape 关闭 + keep-alive 兜底
├── useEventBarActions.ts    # 底部操作栏：点赞/分享数查询与切换（封装底层 API 调用）
└── useShellPatch.ts         # 壳工程 bug 修复：劫持 window.scrollTo 丢弃壳的异常跳顶调用
```

**与 `utils/` 的核心区别**：

| | `hooks/` | `utils/` |
|---|---|---|
| **依赖** | 依赖 Vue 响应式体系（`watch`/`onMounted`/`onActivated` 等生命周期） | 无 Vue 依赖，纯函数 |
| **输入** | `options` 对象（通常含 `Ref<>` 类型） | 普通值（string/number/object） |
| **输出** | 响应式绑定（`Ref<>`/`ComputedRef<>`）+ 方法 | 纯计算结果 |
| **副作用** | 有（DOM 操作、事件监听、keep-alive 生命周期） | 无 |
| **多端守卫** | 内部用 `isMiniProgram()` 做 H5/MP 分支 | 不关心平台 |

**典型案例 1 — useOverlayLifecycle（浮层通用能力复用）**：

```typescript
// 消费方只需一行调用，所有副作用由 hook 内管
useOverlayLifecycle({
  visible: ref(true),     // ← Ref<boolean>，开闭自动触发锁/解锁
  emit,                   // ← 用于 trigger('close')
  lockScroll: true,       // ← 默认 true，H5 端 body fixed + overflow:hidden
  escClosable: true,      // ← 默认 true，Escape 键关闭
});

// hook 内部自动处理：
// - watch(visible) → visible=true 时锁 body 滚动 + 监听 keydown
// - watch(visible) → visible=false 时解锁 + 摘除监听
// - onBeforeUnmount → 兜底解锁
// - onDeactivated → keep-alive 失活时解锁（否则 body 锁残留到上一页）
// - onActivated → 再激活且浮层仍开时重新加锁
// - isMiniProgram() → 小程序端直接 return noop（pages.json disableScroll:true 已锁页）
```

**典型案例 2 — useShellPatch（跨模块通用的壳缺陷修复）**：

壳工程 (`app-shell-v2`) 的 `body.focusout` 事件里存在 `scrollTo(0, -scrollTop)` 的 bug，任何按钮点击后失焦都会导致页面跳顶。该 hook 通过引用计数劫持 `window.scrollTo`，识别并丢弃 `Y < 0` 的错误调用，组件卸载后还原，多实例互不干扰。

**判断一段逻辑该放 hooks 还是组件内**：
- 只被 1 个组件用 → 留在组件内
- 被 2+ 个组件用，且涉及 Vue 生命周期 → 抽成 hook
- 被 2+ 个组件用，但不涉及 Vue → 抽成 `utils/`

#### 10. `components/` — 内部子组件

模块自己的子组件目录，不在 `libProperties.js` 中导出，只被 `Index.vue` 或其他内部组件引用。职责边界:父组件管数据和事件编排，子组件只负责渲染和 emit。

#### 11. `utils/` — 纯函数工具

```typescript
// module-detail-page/utils/format.ts   — 时间/涨跌幅格式化
// module-detail-page/utils/watchlist.ts — 加收藏接口调用
```

不依赖 Vue、不 import 组件，输入→输出纯计算。方便单元测试单独覆盖。

#### 12. `pages/` — 多页面模块的次级路由页面

单页面模块不需要；如果模块有多个路由页面（如列表页→详情页），次页面放这里。`app-discovery` 没有这个目录但 `module-etf-page` 有。

#### 13. `assets/` — 静态资源

图片、字体、SVG 等。避免硬编码 CDN URL 到组件模板，统一管理便于替换。

### 根 `Index.vue` 脚手架陷阱

部分 Hel 模块的根级 `Index.vue` 并非真实业务代码，而是模块创建时自动生成的**脚手架模板**，典型特征：

```js
// app-discovery/Index.vue — 模板文件，从未被任何壳路由使用
setup() {
  const test = ref('Hello World');              // ← 占位数据
  AppBridge.toast('hello');                   // ← API 使用示例
  // 精简版判断
  const isLite = AppBridge.SHELL === PlatformEnum.LITE;
  // ...
}
```

#### 判断根 `Index.vue` 是否为脚手架的方法：

1. 打开 `entrance/libProperties.js`，看 `lib.Index` 对应的实际文件路径
2. 如果该文件包含 `Hello World`、模板注释说明、`TestComponent` 等占位内容 → **脚手架**
3. 真实的业务入口是 `libProperties.js` 中其他命名导出的组件（如 `lib.ContentDetail` → `components/content-detail/index.vue`）

#### 结论

- **单页面模块**：根 `Index.vue` 通常是真实入口（如 `module-detail-page`）
- **多页面/大型模块**：根 `Index.vue` 往往是脚手架，业务代码在 `components/` 下按语义命名，通过 `libProperties.js` 对外导出

### 壳工程各目录的作用

#### 1. `src/routes/` — 路由体系（壳最重要的能力）

壳通过 vue-router 定义所有页面路由，并在路由定义中关联 Hel 子模块：

```js
// src/routes/modules/core/discover.js
{
  path: '/discover/content-detail/detail',
  name: 'investmenttopdetail',
  component: () => import('@/pages/discover/content-detail/detail.vue'),  // ← 容器页
  props: true,
  meta: { busi: 'news', keepAlive: true },
}
```

```
用户访问 URL
  → vue-router 匹配路由 path
  → 异步加载容器页 component
  → 容器页内部 preFetchLibApi('app-discovery')
  → Hel 从 CDN 拉取子模块代码
  → 容器页拿到 lib.ContentDetail 渲染
```

**关键文件**：
| 文件 | 作用 |
|------|------|
| `routes/index.js` | 创建 Router 实例，合并全部路由，注册全局前置/后置守卫 |
| `routes/modules/core/` | 按业务域拆分路由文件，每个文件 `export default [路由数组]` |
| `routes/hooks/` | 路由切换时的通用逻辑（标题更新、数据上报、权限校验） |

#### 2. `src/pages/` — 容器页（壳适配层入口）

```vue
<!-- src/pages/discover/content-detail/detail.vue -->
<template>
  <ContentDetail :event-id="eventId" @ai-ask="onAiAsk" />
</template>
<script>
import { preFetchLibApi } from '@/service/useHel';
export default {
  components: {
    ContentDetail: async () => {
      const lib = await preFetchLibApi('app-discovery');
      return lib.ContentDetail;
    },
  },
};
</script>
```

**容器页的职责**：
- 通过 `preFetchLibApi` 加载 Hel 子模块
- 通过 `provide('appBridge', AppBridge)` 向子树注入壳能力
- 管理全局浮层（如 AI 半屏、隐私协议弹窗）的生命周期
- 处理分享、路由参数解析等壳级逻辑

> 容器页与 Hel 适配层（如 `app-discovery/content-detail/index.vue`）的关系见「Hel 模块标准目录结构」章节的壳适配层说明。

#### 3. `src/service/useHel.ts` — Hel 微前端加载器

```typescript
// 核心职责
import { bindVueRuntime } from '@company/st-hel';

// ① 向 Hel 注入 Vue 运行时（子模块共享壳的 Vue 实例，避免重复打包）
bindVueRuntime({ Vue });
window.VueCompositionAPI = VueCompositionAPI;  // Composition API 全局注入
window.AppBridge = appBridgeExternal;      // AppBridge 全局注入
window.pinia = piniaExternal;                  // Pinia 全局注入

// ② 配置 Hel SDK（指定壳 ID、CDN 域名、版本元数据地址）

  id: 'app_h5_lite',
  host: 'https://app.example.com',
  metaVersionUrl: '...',  // ← 控制子模块版本拉取的配置文件
};

// ③ 导出 preFetchLibApi('app-discovery') 供容器页使用
```

这是壳最核心的基础设施文件——**所有 Hel 子模块都由它加载**。

#### 4. `src/App.vue` — 应用根组件

### 壳工程 vs Hel 子模块的核心区别

| 维度 | 壳工程（app-shell） | Hel 子模块（app-discovery） |

## 壳工程加载 Hel 模块全流程

本章以「用户访问 `app-shell` 壳中的 `ContentDetail` 页面」为例，逐步说明从浏览器输入 URL 到子模块组件渲染完成的完整过程。

---

### 全流程总览

```
用户浏览器
  └─ https://app.example.com/#/content-detail/detail?event_id=xxx
       │
       ├── 【阶段 1】壳启动 → main.ts 创建 Vue 实例
       │
       ├── 【阶段 2】Hel 框架引导 → useHel.ts 注入运行时
       │
       ├── 【阶段 3】路由匹配 → vue-router 找到容器页路径
       │
       ├── 【阶段 4】容器页加载 → dynamic import() 加载 detail.vue
       │
       ├── 【阶段 5】Hel 模块拉取 → preFetchLibApi 从 CDN 获取子模块
       │
       ├── 【阶段 6】组件渲染 → lib.ContentDetail 挂载到模板
       │
       └── 【阶段 7】[调试模式] debug_hel 从本地 dev server 加载
```

### 阶段 1：壳启动

壳是一个标准 Vue 2 SPA，入口在 `src/main.ts`：

```typescript
// src/main.ts
import Vue from 'vue';
import App from './App.vue';
import router from './routes';
import store from './store';

// ① 全局注册基础组件（Navbar、ShareGuide 等）
// ② 注册全局指令和过滤器
// ③ 初始化监控（Monitor）、登录态（login）、统计（stat）

new Vue({
  router,    // ← URL → 页面的映射
  store,     // ← 全局状态（用户信息、渠道号等）
  render: h => h(App),
}).$mount('#app');

// 此时 App.vue 被渲染：
// <template>
//   <keep-alive>
//     <router-view v-if="$route.meta.keepAlive" />  ← 路由出口
//   </keep-alive>
//   <router-view v-if="!$route.meta.keepAlive" />
// </template>
```

> **关键点**：壳刚启动时 `<router-view>` 是空的，需要等路由匹配后才能决定渲染哪个容器页。

---

### 阶段 2：Hel 框架引导

在壳启动过程中（通常在 main.ts 顶部或 App.vue 的 `setup()` 中），`useHel.ts` 必须最先执行，因为它要向 `window` 对象注入 Hel 子模块依赖的全部运行时：

```typescript
// src/service/useHel.ts（简化示意）
import { bindVueRuntime } from '@company/st-hel';

// ① 向全局注入 Vue 运行时 —— 子模块不自己打包 Vue，而是共享壳的
bindVueRuntime({ Vue });
window.VueCompositionAPI = VueCompositionAPI; // Composition API 插件
window.AppBridge = appBridgeExternal;         // 多端桥接对象
window.pinia = piniaExternal;                 // 全局状态库

// ② 配置 Hel SDK —— 告诉它去哪里下载子模块
const MF_SDK_CONFIG = {
  id: 'app_h5_lite',                          // 壳的唯一 ID
  host: 'https://app.example.com',            // CDN 域名
  metaVersionUrl: 'https://.../meta.json',    // 子模块版本元数据文件
};

// ③ 对 Hel SDK 暴露 preFetchLibApi 供容器页使用
export { preFetchLibApi } from '@company/hel-lib-proxy';
```

**为什么必须注入到 `window`？**

子模块被拉取后在浏览器中直接执行，它处于独立的 JS 作用域（不是壳的 webpack 模块系统），无法通过 ES `import` 引用壳内的模块。它只能从 `window.Vue`、`window.AppBridge` 等全局变量获取依赖：

```javascript
// 子模块 main.js（运行时执行）
import { libReady } from '@company/hel-lib-proxy';
// ↑ 这个 import 来自子模块自己的打包，不经过壳

// 子模块组件（运行时执行）
const Vue = window.Vue;             // ← 壳注入的 Vue 运行时
const appBridge = Vue.inject?.('appBridge') ?? window.AppBridge;
// ← 壳注入的多端能力，优先从 provide/inject 获取
```

### 阶段 3：路由匹配

用户访问 `https://app.example.com/#/content-detail/detail?event_id=evt_001`，vue-router 收到 hash 变化后开始解析：

```
URL 解析：
  hash:     #/content-detail/detail?event_id=evt_001
  path:     /content-detail/detail
  query:    { event_id: 'evt_001' }
```

路由定义在 `src/routes/modules/core/discover.js` 中：

```javascript
// src/routes/modules/core/discover.js
export default [
  // ... 其他路由 ...

  {
    // path 匹配当前 URL
    path: '/content-detail/detail',

    // name 供子模块内 AppRouter.routeTo({ name: '...' }) 使用
    name: 'investmenttopdetail',

    // 容器页 —— 下一步要加载的目标
    component: () => import(
      /* webpackChunkName: "content-detail" */
      '@/pages/content-detail/detail.vue'
    ),

    // $route.query 自动映射为组件的 props
    props: true,

    meta: {
      busi: 'info',         // 业务类型（数据上报用）
      signature: true,      // 需登录态
      keepAlive: true,      // 页面缓存（返回不销毁）
      scrollToTop: true,    // 进入时滚回顶部
    },
  },
];
```

**路由配置决定了什么？**

| 字段 | 作用 |
|------|------|
| `path` | URL → 路由 的匹配规则 |
| `component` | 路由 → 容器页 的映射（webpack 懒加载分块） |
| `props: true` | 将 query 参数变为容器的 props |
| `meta.keepAlive` | 决定 App.vue 中 `<keep-alive>` 是否缓存该页面 |

> **注意**：`component` 加载的是**容器页**（`pages/content-detail/detail.vue`），而非 Hel 子模块本身。子模块是在容器页内部通过 `preFetchLibApi()` 拉取的。

### 阶段 4：容器页加载

vue-router 匹配到路由后，webpack 异步加载容器页代码（`webpackChunkName: "content-detail"`）：

```vue
<!-- src/pages/content-detail/detail.vue -->
<template>
  <div class="detail-page">
    <!-- 加载态 -->
    <div v-if="isLoading" :style="{ paddingTop: statusBarHeight }">
      <st-status type="loading" />
    </div>

    <!-- 渲染 Hel 子模块组件（ContentDetail 来自 preFetchLibApi 的返回值） -->
    <ContentDetail
      v-if="!isLoading"
      :params="pageParams"
      @ai-ask="handleAiAsk"
      @refresh-success="handleRefreshSuccess"
    />
  </div>
</template>

<script lang="ts">
import { defineComponent, ref, computed } from '@vue/composition-api';
import { preFetchLibApi } from '@/service/useHel';
import AppBridge from '@company/shared-base/bridge';

export default defineComponent({
  name: 'ContentDetailShell',
  props: {
    event_id: { type: String, default: '' },    // ← 由 router.props: true 自动传入
  },
  setup(props) {
    const isLoading = ref(true);

    // ① 构造传入子模块的参数
    const pageParams = computed(() => ({
      event_id: props.event_id,
      symbol: '',
      pageType: 'detail',
    }));

    // ② 向子树注入壳能力（子模块内通过 inject('appBridge') 获取）
    provide('appBridge', AppBridge);

    // ③ 拉取 Hel 子模块（异步 → 触发阶段 5）
    const contentDetailModule = ref(null);
    preFetchLibApi('app-discovery').then((lib) => {
      contentDetailModule.value = lib;
      isLoading.value = false;
    });

    // ④ 处理子模块 emit 上来的事件
    const handleAiAsk = (question) => {
      // 壳负责渲染 AI 半屏（子模块不知道壳用什么方式展示 AI）
    };

    return {
      isLoading,
      pageParams,
      ContentDetail: computed(() => contentDetailModule.value?.ContentDetail),
      handleAiAsk,
      handleRefreshSuccess,
    };
  },
});
</script>
```

**容器页的职责总结**：

| 职责 | 说明 |
|------|------|
| **加载子模块** | 调用 `preFetchLibApi('app-discovery')` |
| **参数透传** | 将路由 query → props 原样传给子模块 |
| **壳能力注入** | `provide('appBridge', AppBridge)` 让子模块通过 `inject` 获取 |
| **事件上行** | 接收子模块的 emit（`@ai-ask`、`@refresh-success`）并调用壳级能力 |
| **管理全局 UI** | AI 半屏、隐私协议弹窗等跨页面 UI 由容器页管理生命周期 |

### 阶段 5：Hel 模块拉取

`preFetchLibApi('app-discovery')` 的调用触发了 Hel SDK 的完整加载链路：

```
preFetchLibApi('app-discovery')
  │
  ├─ 1. 检查内存缓存
  │     if (Hel 缓存中有 'app-discovery') → 直接返回，跳过后续步骤
  │
  ├─ 2. 【生产模式】从 CDN 获取
  │     │
  │     ├─① 请求元数据文件（metaVersionUrl）
  │     │     GET https://app.example.com/hel-dist/meta.json
  │     │     返回: { "app-discovery": { "version": "20260731143000", "js": "...url..." } }
  │     │
  │     ├─② 请求模块 JS 文件
  │     │     GET https://app.example.com/hel-dist/app-discovery/20260731143000/index.js
  │     │     返回: 子模块的 webpack 打包产物（含 main.js + libProperties.js + 所有组件）
  │     │
  │     └─③ 执行模块代码
  │           │
  │           ├─ 子模块 main.js 执行：
  │           │    import { libReady } from '@company/hel-lib-proxy';
  │           │    libReady('app-discovery', { Index, ContentDetail, ... });
  │           │    // ↑ 将组件注册到 Hel 的内存注册表
  │           │
  │           └─ Hel SDK 返回模块的 export 对象给调用方
  │                preFetchLibApi 的 Promise resolve(lib)
  │                lib = { Index, ContentDetail, DetailPage, ... }
  │
  ├─ 3. 【调试模式】从本地 dev server 获取
  │     if (URL 中有 ?debug_hel=1&local_ip=192.168.1.x&debug_module=app-discovery)
  │       → 不从 CDN 拉取
  │       → 改为请求 http://192.168.1.x:8010/hel-dist/app-discovery/xxx/index.js
  │       → 其余流程与生产模式相同
  │
  └─ 4. 写入缓存
        Hel SDK 将模块缓存到内存，下次 preFetchLibApi 同一模块直接返回
```

**子模块 main.js 与 libProperties.js 的分工**：

```javascript
// main.js —— 模块被加载时自动执行，负责注册
import { appGroupName } from './package.json';
import { libReady } from '@company/hel-lib-proxy';

(async function () {
  const libProperties = await import('./entrance/libProperties');
  libReady(appGroupName, libProperties.default);
  //           ↑ 'app-discovery'  ↑ { Index, ContentDetail, DetailPage, ... }
}()).catch(console.error);

// libProperties.js —— 定义对外暴露哪些组件
import Index from '../Index.vue';
import ContentDetail from '../components/content-detail/index.vue';
import DetailPage from '../components/detail-page/h5/index.vue';

export default { Index, ContentDetail, DetailPage, /* ... */ };
```

**运行时的代码执行顺序**：

```
1. Hel SDK 下载 index.js
2. index.js 中的 main.js 立即执行（IIFE）
3. main.js 动态 import() libProperties.js → 拿到组件引用
4. main.js 调用 libReady('app-discovery', 组件对象) → 注册到 Hel 内存注册表
5. Hel SDK 收到注册通知 → 将组件对象作为 Promise 结果返回
6. 容器页拿到 lib = { ContentDetail, ... }
7. 容器页的 computed 属性 ContentDetail 从 lib.ContentDetail 拿到的就是那个 Vue 组件
```

### 阶段 6：组件渲染

容器页在 `preFetchLibApi` 返回后将结果赋值给 Vue 的响应式数据：

```vue
<template>
  <!-- isLoading: false → v-if 条件满足 → 渲染子模块组件 -->
  <ContentDetail
    v-if="!isLoading"
    :params="pageParams"
    @ai-ask="handleAiAsk"
  />
</template>

<script>
export default defineComponent({
  setup() {
    // 阶段 5 完成后: contentDetailModule.value = { ContentDetail, ... }
    const contentDetailModule = ref(null);

    // 容器页的 ContentDetail = 子模块导出的 ContentDetail.vue 组件
    const ContentDetail = computed(() => contentDetailModule.value?.ContentDetail);

    return { ContentDetail };
  },
});
</script>
```

**子模块组件内部如何获取壳能力**：

子模块组件（如 `app-discovery/components/content-detail/index.vue`）不依赖任何具体平台实现，它通过 Vue 的依赖注入获取壳能力：

```typescript
// 子模块组件内部
import { inject } from '@vue/composition-api';

export default defineComponent({
  setup() {
    // 从壳注入的对象中获取多端能力
    const appBridge = inject('appBridge');
    // appBridge 和壳里的是同一个对象（引用传递）

    const loadData = async () => {
      // 子模块不关心自己在 H5 还是客户端
      // 只调用统一 API，壳在注入时就处理了多端差异
      const data = await appBridge.request('/api/detail', 'GET', { id: eventId });
    };

    const jumpToDetail = () => {
      appBridge.router.routeTo({ name: 'other-page' });
      // 壳的路由表保证 'other-page' 存在
    };
  },
});
```

**渲染时的 Vue 实例关系**：

```
壳 App.vue（独立 Vue 实例，有自己的组件树）
  └─ <keep-alive>
       └─ <router-view>                          ← 壳的组件
            └─ detail.vue（容器页）               ← 壳的组件
                 └─ <ContentDetail>              ← 子模块的组件（共享 window.Vue）
                      ├─ <ContentDetailHeader>   ← 子模块的子组件
                      ├─ <ContentDetailTab>      ← 子模块的子组件
                      └─ ...
```

所有子模块组件共用壳注入的 `window.Vue` 运行时，它们是同一个 Vue 构造函数的不同组件子树，响应式系统、生命周期钩子等底层机制完全互通。

### 阶段 7：调试模式（debug_hel）

在本地开发子模块时，不需要每次都发布到 CDN。Hel 提供了 `debug_hel` 机制，从本地 dev server 加载代码：

#### 前置条件

```bash
# 终端 1：启动壳 dev server（HEL_DEBUG 模式）
cd app-shell
npm run serve:hel
# 等价于 HEL_DEBUG=true npm run serve
# → 壳在 http://localhost:8080 启动，等待 debug_hel 参数

# 终端 2：启动子模块 dev server
cd monorepo-project/packages/news/app-discovery
npm run serve
# → 子模块在 http://localhost:8010 启动
```

#### 调试 URL

```
http://localhost:8080/?debug_hel=1&local_ip=192.168.1.100&debug_module=app-discovery#/content-detail/detail?event_id=evt_test
                       └─── 这三个参数必须在 # 之前 ───┘               └── 路由 hash ──┘
```

#### 参数作用

| 参数 | 含义 |
|------|------|
| `debug_hel=1` | 开启 Hel 调试模式 |
| `local_ip=192.168.1.100` | 子模块 dev server 的局域网 IP（**不能用 127.0.0.1**） |
| `debug_module=app-discovery` | 指定哪个模块从本地加载 |

#### 调试模式下的加载路径变化

```
生产模式：
  preFetchLibApi('app-discovery')
    → CDN 拉取 https://app.example.com/hel-dist/app-discovery/xxx/index.js

调试模式（debug_hel）：
  preFetchLibApi('app-discovery')
    → 本地拉取 http://192.168.1.100:8010/hel-dist/app-discovery/xxx/index.js
```

剩余流程完全一致（执行 main.js → libReady → 返回组件 → 渲染）。

### 常见问题与排查

#### Q1: 页面显示空白 / 加载转圈

| 可能原因 | 排查方法 |
|---------|---------|
| Hel 模块未发布到 CDN | 打开 Network 面板，检查 `hel-dist/.../index.js` 是否返回 404 |
| `window.Vue` 未注入 | 浏览器控制台执行 `console.log(window.Vue)`，应为 Vue 构造函数 |
| 容器页 `preFetchLibApi` 未调用或被注释 | 检查容器页 setup 中是否有该调用 |
| 模块 `appGroupName` 与 `preFetchLibApi` 参数不一致 | 检查子模块 `package.json` 的 `appGroupName` 字段 |

#### Q2: debug_hel 不生效

| 可能原因 | 解决方案 |
|---------|---------|
| 壳没有以 `HEL_DEBUG` 模式启动 | 必须用 `npm run serve:hel`，不能用 `npm run serve` |
| `local_ip` 用了 `127.0.0.1` | 改为局域网 IP（`ipconfig` 查看），手机真机调试更必须用局域网 IP |
| 三个 debug 参数写在了 `#` 后面 | `debug_hel`、`local_ip`、`debug_module` 必须在 `#` 之前 |
| 子模块 dev server 未启动（端口 8010 无进程） | `netstat -ano | findstr :8010` 检查，需 `npm run serve` 子模块 |

#### Q3: 子模块组件报错 `inject('appBridge')` 返回 undefined

容器页必须在调用 `preFetchLibApi` 之前先 `provide('appBridge', AppBridge)`。如果容器页自己都没 provide，子模块无法获取。

#### Q4: 子模块内 `AppRouter.routeTo()` 跳转失败

子模块路由名称（如 `name: 'other-page'`）必须在壳的 `routes/` 中有对应定义。子模块本身不注册路由，它只是调用壳的路由表。如果壳路由变更了 name 而子模块没同步更新，跳转就会 404。

### 每个文件/目录的作用说明

#### 1. `main.ts` — 应用启动入口

```typescript
// src/main.ts
import { createApp } from 'vue';
import { createPinia } from 'pinia';
import App from './App.vue';
import router from './router';

const app = createApp(App);

app.use(createPinia());    // ① 全局状态管理 — 所有页面共享
app.use(router);           // ② 路由系统 — URL → 页面映射

app.mount('#app');         // ③ 挂载到 index.html 的 <div id="app">
```

**与 Hel 架构的关键区别**：
- **单体 SPA**：一行 `createApp(App).mount('#app')` 直接启动，所有代码都在同一个包里
- **Hel 架构**：子模块没有 `main.ts` 的 `createApp` 调用，只有 `main.js` 的 `libReady()` 注册

#### 2. `App.vue` — 应用布局骨架

```vue
<template>
  <a-layout class="app-layout">
    <!-- 左侧导航 -->
    <AppSidebar />

    <!-- 右侧内容区 -->
    <a-layout>
      <a-layout-content>
        <router-view />     <!-- 当前路由对应的页面在此渲染 -->
      </a-layout-content>
    </a-layout>
  </a-layout>
</template>

<script setup lang="ts">
import { AppSidebar } from '@/components/layout';
</script>
```

**注意**：`App.vue` 已直接包含 `AppSidebar` 并排列局，不像 Hel 架构需要 `<keep-alive>` 区分页面缓存——单体 SPA 的页面切换由 `<router-view>` 自动处理。

#### 3. `router/index.ts` — 路由集中定义

```typescript
// 全部 12 条路由都在一个文件里
const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    { path: '/',             name: 'chat',            component: () => import('../views/ChatView.vue') },
    { path: '/sessions',     name: 'sessions',        component: () => import('../views/SessionsView.vue') },
    { path: '/skills',       name: 'skills',          component: () => import('../views/SkillsView.vue') },
    { path: '/skills/:name/edit', name: 'skill-editor', component: () => import('../views/SkillEditor.vue') },
    { path: '/knowledge-base', name: 'knowledge-base', component: () => import('../views/KnowledgeBaseView.vue') },
    { path: '/tool-logs',    name: 'tool-logs',       component: () => import('../views/ToolLogsView.vue') },
    { path: '/automation',   name: 'automation',      component: () => import('../views/AutomationView.vue') },
    { path: '/memory',       name: 'memory',          component: () => import('../views/MemoryView.vue') },
    { path: '/config',       name: 'config',          component: () => import('../views/ConfigView.vue') },
    { path: '/health',       name: 'health',          component: () => import('../views/HealthView.vue') },
  ],
});
```

**与 Hel 架构的关键区别**：

| | 单体 SPA | Hel 架构 |
|---|---------|---------|
| **路由定义位置** | 项目内的 `router/index.ts` 单个文件 | 壳工程的 `routes/modules/` 目录，按业务域拆分 |
| **component 指向** | `../views/XxxView.vue`（项目内的本地文件） | `../pages/容器.vue`（壳内的容器页，间接拉取子模块） |
| **路由数量** | 12 条，集中管理 | 数百条，分散在数十个壳路由文件中 |
| **History 模式** | `createWebHistory()`（无 `#`，需服务器配合） | Hash 模式 `#/path`（兼容微信 WebView） |

#### 4. `views/` — 页面视图

每个 `.vue` 文件对应路由表中的一条路由，是用户看到的**完整页面**。使用 `<script setup>` 语法（Vue 3 原生 Composition API）：

```vue
<template>
  <div class="chat-page">
    <ChatContainer :session-id="currentSessionId" />
  </div>
</template>

<script setup lang="ts">
import { ref } from 'vue';
import { useRoute } from 'vue-router';
import { useChatStore } from '@/stores/chat';
import { ChatContainer } from '@/components/chat';

const route = useRoute();
const chatStore = useChatStore();

// 页面级逻辑：数据加载、路由参数解析、页面级状态

// 不需要 return，<script setup> 自动将顶层变量暴露给 <template>
</script>

<style scoped>
.chat-page {
  height: 100%;
  display: flex;
}
</style>
```

> **注意**：Vue 3 的 `<script setup>` 是编译时语法糖，相比 Hel 架构的 `defineComponent({ setup() { ... return {} } })` 更简洁，不需要手动 `return`。

#### 5. `components/` — 可复用组件

按功能域分目录，不直接对应路由：

```
components/
├── layout/           ← 布局级组件（全局只用一次）
│   └── AppSidebar.vue
├── chat/             ← 对话域组件（在 ChatView 中使用）
│   ├── ChatContainer.vue
│   ├── MessageList.vue
│   ├── MessageInput.vue
│   └── AttachmentBar.vue
└── common/           ← 通用组件（跨多个 views 使用）
```

**与 `views/` 的区分**：
- `views/` 代表**一个完整页面**（对应路由），可以直接访问 store 和 route
- `components/` 代表**一个可复用的 UI 片段**（不直接对应路由），通过 props/emit 通信

#### 6. `stores/` — Pinia Setup Store

采用 Composition API 风格定义（与 `<script setup>` 语法一致）：

```typescript
// stores/workspace.ts
import { defineStore } from 'pinia';
import { ref, computed } from 'vue';

export const useWorkspaceStore = defineStore('workspace', () => {
  // state
  const current = ref('');
  const history = ref<string[]>([]);
  const loading = ref(false);

  // getters
  const currentName = computed(() => {
    if (!current.value) return '未选择工作区';
    const parts = current.value.split(/[/\\]/);
    return parts[parts.length - 1] || current.value;
  });

  // actions
  async function init() { /* 拉取已授权工作区列表 */ }
  async function select(path: string) { /* 切换到新工作区 */ }
  async function authorize(path: string): Promise<string> { /* 授权新工作区 */ }

  return { current, currentName, history, loading, init, select, authorize };
});
```

**与 Hel 架构中模块级单例 store 的区别**：

| | 单体 SPA Pinia Store | Hel 架构模块级单例 |
|---|---|---|
| **注册方式** | `createPinia()` + `app.use(pinia)` | 纯 JS 模块缓存（`const state = reactive({})`） |
| **作用域** | 全局，所有页面共享 | 仅在当前 Hel 子模块内有效 |
| **DevTools** | Vue DevTools 中可见 Pinia 面板 | 不可见 |
| **跨模块共享** | 天然支持（全局唯一） | 不支持（各子模块是独立包） |

#### 7. `api/index.ts` — axios 实例 + 拦截器

```typescript
// api/index.ts
import axios from 'axios';

const instance = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || 'http://localhost:8000/api',
  timeout: 30000,
});

instance.interceptors.response.use(
  (response) => response.data,     // 自动解包，返回 response.data
  (error) => Promise.reject(error),
);

export default {
  get: <T>(url: string): Promise<T> => instance.get(url),
  post: <T>(url: string, data?: unknown): Promise<T> => instance.post(url, data),
  put: <T>(url: string, data?: unknown): Promise<T> => instance.put(url, data),
  delete: <T>(url: string): Promise<T> => instance.delete(url),
};
```

**与 Hel 架构 `AppBridge.request` 的区别**：
- **单体 SPA**：直接用 `axios`，标准 HTTP 调用，适用于单一 Web 环境
- **Hel 架构**：必须用 `AppBridge.request`，底层可能转换为 `wx.request`（客户端）或 `sendBeacon`（跨场景），抹平了 H5 / 客户端 / App 的多端差异

#### 8. `api/{domain}.ts` — 业务接口文件

每个文件对应一个后端模块，导入共享的 axios 实例：

```typescript
// api/chat.ts
import api from './index';

export interface ChatResponse { content: string; session_id: string | null; }

export const chatApi = {
  send: (data: { message: string; session_id?: string }): Promise<ChatResponse> =>
    api.post('/chat', data),
};
```

**与 Hel 架构 `api/{service}/` 的区别**：
- **单体 SPA**：接口文件按业务域平铺（`chat.ts`、`workspace.ts`）
- **Hel 架构**：每个接口是一个**目录**（`api/{service}/index.ts` + `types.ts` + `mock.ts` 三层结构），因为子模块需要 mock 数据实现脱离壳的独立开发和 E2E 测试

#### 9. `utils/` — 纯函数工具

```typescript
// utils/markdown.ts — Markdown 解析、代码高亮、流式渲染辅助
// utils/toolDisplay.ts — 工具调用格式化为可读 UI（参数截断、状态图标映射）
```

纯函数，不依赖 Vue。与 Hel 架构中 `utils/` 的定位完全一致。

#### 10. `vite.config.ts` — 构建与开发配置

```typescript
// vite.config.ts
export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) },
  },
  server: {
    port: 5173,
    proxy: {
      '/api': {
        target: 'http://localhost:8000',  // ← 后端地址
        changeOrigin: true,
      },
    },
  },
});
```

**与 Hel 架构的构建配置差异**：

| | 单体 SPA（Vite） | Hel 架构（Vue CLI + Webpack） |
|---|---|---|
| **构建工具** | Vite 7（原生 ESM，秒级热更新） | Webpack 5（传统打包，冷启动 30-60s） |
| **开发体验** | 改代码 → 毫秒级热替换 | 改代码 → 秒级增量编译 |
| **代理配置** | `vite.config.ts` 的 `server.proxy` | `vue.config.js` 的 `devServer.proxy` |
| **产物格式** | 标准 SPA（index.html + assets） | 壳 → SPA；子模块 → Hel 包（通过 CDN 分发） |

---

### 单体 SPA 与 Hel 微前端架构的核心差异总结

| 维度 | 单体 SPA（MyClaw） | Hel 微前端（stock-union） |
|------|-------------------|------------------------|
| **Vue 版本** | Vue 3.5 | Vue 2.6 |
| **组件语法** | `<script setup>`（编译时语法糖） | `defineComponent({ setup() {} })`（运行时 API） |
| **构建工具** | Vite 7（ESM 原生） | Vue CLI 5 + Webpack 5 |
| **UI 框架** | Ant Design Vue 4（开箱即用） | 无框架，手写 BEM 组件 |
| **路由** | `createWebHistory`（单文件集中） | Hash 模式（壳内按业务域拆分） |
| **状态管理** | Pinia（全局唯一 Store） | 模块级 reactive 单例或 Vuex |
| **HTTP 请求** | `axios`（标准 HTTP） | `AppBridge.request`（多端桥接） |
| **部署模型** | 打包 → 部署 Nginx | 壳部署 + 子模块 CDN 分发 |
| **多端支持** | 桌面 Web 单端 | H5 / 客户端 / App 多端 |
| **发行方式** | 整体发版（影响全部页面） | 子模块独立发版（互不阻塞） |
| **项目规模** | 小型项目（10-20 页面） | 大型项目（数百页面，多团队并行） |
| **学习曲线** | 低（标准现代前端栈） | 高（需理解 Hel + 壳 + 多端概念） |

### 何时选择哪种架构

| 场景 | 推荐架构 |
|------|---------|
| 个人项目 / 小团队 / 单一平台 | 单体 SPA |
| 多团队协作 / 数百页 / 需独立发版 | Hel 微前端 |
| 需同时跑 H5 + 客户端 + App 多端 | Hel 微前端（多端桥接层复用） |
| 新手学习 / 快速原型 | 单体 SPA |
| 已有壳工程 / 团队熟悉 Hel 机制 | Hel 微前端
